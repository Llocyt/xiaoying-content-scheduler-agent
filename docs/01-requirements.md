# 需求与成功标准

## 用户与目标

内容运营人员提供素材 ID、时间要求与合成素材库，得到可追溯的审核结果和无越权的发布排期草稿。系统减少人工查资料、查冲突、核对保存结果的操作，最终发布仍由用户在其他系统完成。

## 范围

实现题 1 的 CLI。一次处理一个素材，多个素材可分别调用，使用相同 SQLite 库协调已确认草稿的时段。输入资料与规则位于 `data/fixtures.json`，替换资料可传 `--data PATH`。

输入必含 `request_id`、`asset_id`、`requested_slot`，可含 `hard_requirement` 和调用者明确提供的 `confirmed_slot`。所有时段限定 `+08:00`、同日整点；候选窗口只来自资料，不进行任意日历搜索。

## 验收条件

| 验收点 | 成功标准 |
|---|---|
| 正常排期 | 审核通过，原时段空闲；实际持久化，报告草稿回执 |
| 信息缺失 | 模型可补查；补查仍不足则不保存，并列出缺失字段 |
| 规则风险 | 版权未通过、禁用短语或需人工审核时阻止保存 |
| 时段冲突 | 观察占用后查替代；未经明确确认不得改硬性要求 |
| 重复提交 | 相同请求只产生一份草稿；同 ID 改基本请求报冲突 |
| 保存失败 | 输出失败和真实错误，不伪造 draft_id 或成功状态 |
| 用户确认 | 同一请求确认精确替代时段，更新同一草稿并重新检查可用性 |
| 执行上限 | 默认最多 10 轮，最多允许设置 30 轮；达到上限明确未完成 |

每次模型调用只选择一个工具，因此工具执行次数不超过轮数。`finish` 也计入轮数。未知工具和非法参数也消耗轮数，不能绕过上限。

## 必须守住的边界

模型选择工具，但不能更改请求、规则或确认授权；没有发布工具。模型的自然语言说明只进入 Trace。最终报告依据已执行的审核、查询和持久化事实生成。

待确认替代建议并不等于改变原要求。保存 pending 草稿时同时保留 `requested_slot` 与 `suggested_slot`，并要求用户确认；只有已确认草稿才占位。
